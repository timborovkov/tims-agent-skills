# Compliance And Legal Preferences

- Non-trivial public products need a compliance/legal documentation pass before launch.
- Include `LICENSE` at the repo root when the project is distributed, open source, or has unclear reuse terms.
- Include privacy policy and terms of use docs or links for public apps, especially when collecting accounts, analytics, payments, messages, uploaded files, or AI inputs.
- GDPR/privacy posture should be explicit: data collected, purposes, retention, processors/subprocessors, deletion/export path, cookie/analytics behavior, and user contact route.
- Keep compliance docs aligned with actual providers: PostHog, Sentry, Novu, Postmark/Resend, Polar, OpenRouter, Daytona, storage, database, and hosting.
- Do not invent legal certainty. Draft practical docs/checklists and tell the user when lawyer review is needed.
