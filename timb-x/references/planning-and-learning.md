# Planning and learning

## Planning and choosing conversations

Use the requested goal, actual interests, and available experiences to select
opportunities. Check whether a reply still makes sense in the current conversation.
Rank candidates by relevance and the contribution the user can make, with reach as a
secondary consideration. Explain a skip when useful; silence is a valid outcome.

Build plans from real work, questions, and conversations. Leave gaps when there is
nothing worth publishing. Do not impose a daily quota, fixed posting hour, or
mandatory content mix. A plan is a proposal, not scheduled posts or an automation.

For discovery, ask about a recent build decision, failed attempt, surprising result,
or opinion they can defend. Ask only enough to uncover usable material. If the user asks
to save a story bank, retain the source, date, approved details, and uncertainty in
an agreed project file. Do not silently modify personal memory or treat draft
ideas as published events.

## Performance and audience analysis

Use accessible post data or a supplied export; state missing fields. Retain URLs,
measurement date, post age, format, topic, and available metrics. Compare originals,
replies, quotes, and threads separately where possible. Older posts and replies
beneath large accounts have different exposure opportunities.

Report impressions, likes, replies, reposts, profile visits, and conversions
separately. If calculating a rate, state its numerator and denominator; unavailable
metrics are missing, not zero. Do not sum views and reactions into a misleading
engagement score. Follower count is context, not a complete correction for reach.

Look for repeated patterns across comparable posts. Distinguish observation,
hypothesis, and next experiment. Treat a single breakout as a candidate to explore.
Test one meaningful change when practical and judge against the user's goal.
Never promise algorithm multipliers, guaranteed virality, or causal conclusions
from a small observational sample.

Cluster actual replies into questions, disagreement, and useful follow-up themes.
Do not infer private audience demographics or access to a liker list from public
reply data. Recommend conversations because the user has something to contribute.

## Profile review

Read the current profile and establish its purpose. Suggest a bio, display name,
header direction, or pinned post only when requested or relevant to that audit.
Use real work and supported claims; keep their voice rather than constructing a
performative founder persona. Profile edits need authorization just like posts.
