# Timb Trim Detail

## Scope

Default to the diff vs the repo's default branch. Detect the default with:

```bash
git symbolic-ref refs/remotes/origin/HEAD 2>/dev/null | sed 's@^refs/remotes/origin/@@'
```

If that fails, try `main`, `master`, `trunk`, then `develop`, preferring `origin/<name>` over local refs. Refresh `origin/<default>` when possible.

For diff scope, include the union of committed branch changes, staged/unstaged changes, and untracked files:

```bash
git diff --name-only <base>...HEAD
git diff --name-only HEAD
git ls-files --others --exclude-standard
```

Whole-codebase scope means every source file the repo's ignore rules permit.

Always exclude `vendor/`, `third_party/`, `node_modules/`, build outputs, coverage, `.claude/`, `.cursor/`, `.codex/`, `.opencode/`, generated files, minified files, and exact lockfile names. Also exclude files whose first 10 lines contain generator headers such as `Code generated by`, `@generated`, or `AUTO-GENERATED`.

## Public Surface

Public-surface changes require individual opt-in. Treat as public:

- Go: capitalized identifiers outside `internal/`.
- TS/JS: exports from package entrypoints, `exports`, `main`, `module`, or barrel files.
- Python: top-level names not prefixed with `_`, plus `__all__`.
- Rust: `pub` items in non-test, non-`#[doc(hidden)]` modules.
- Ruby: non-private/protected methods on exposed gem classes/modules.

When in doubt, treat it as public.

## Finding Buckets

- `a` Verbose comments: remove narration, keep why/constraints/gotchas.
- `b` Legacy patterns: modernize only when semantics are preserved. Examples: Go `interface{}` to `any`; Python `%`/`.format` to f-strings; simple JS `Object.assign({}, x)` to spreads. Do not blanket-convert `var` or promise chains.
- `c` Dead code: unused imports, unreachable branches, commented-out blocks, never-called private/internal methods. Cross-check with search/LSP.
- `d` Duplication: near-duplicate blocks or existing helpers not reused. Cite both sites.
- `e` Simplification: flatten conditionals, remove redundant checks, simplify booleans.
- `P` Public-surface risk: any of the above touching public exports, signatures, names, or shapes.

For each finding record path/lines, bucket, current/proposed line counts, why, risk, test status, and a short before/after snippet.

## Test Gate

Risk above `none` needs meaningful test coverage. A meaningful test exercises behavior with real inputs and asserts outputs, side effects, branches, permissions, rendering, or errors. A tautological mock does not count.

If coverage is missing, mark `needs-tests-first` and state the concrete assertion to add.

## Report And Approval

Write the report to `<repo>/.claude/trim-report-<YYYY-MM-DD>.md`, or `~/.claude/trim-reports/<repo>-<YYYY-MM-DD>.md` when `.claude/` is unavailable/gitignored.

The report must include scope, files reviewed, estimated line reduction, public API findings, regular findings, risk, tests, and snippets.

Ask the user to choose:

- `all`: every regular finding, excluding `P`.
- `select`: specific regular and/or `P` findings.
- `none`: stop and leave the report.

If `all` is chosen and `P` items exist, ask separately about each public-surface finding.

## Implementation

For each approved finding:

1. Add missing tests first when required.
2. Run those tests against current code to prove they are valid.
3. Apply the refactor.
4. Run project verification gates from `AGENTS.md`, `CLAUDE.md`, or equivalent.
5. Commit one finding at a time if committing, using `trim(<bucket>): <short title>`.

If a finding cannot be salvaged quickly, revert only that finding and continue.

After approved work is green, delete the report and summarize actual line reduction, shipped findings, and skipped findings.
